### Adapter contract

An adapter supplies the checkpoint configuration, stored tensor inventory, logical components, executable capture locations and a loader when available. The generic adapter reads safetensors headers and exposes stored tensors without execution semantics. The Qwen3 adapter adds block, attention, MLP and normalization components and uses the evaluation environment's CPU model loader. The factorized adapter uses the existing factorized loader and associates `left.weight` and `right.weight` with the logical projection. UI tree edges denote containment. The factor view shows the verified execution order (x → B → A) inside that projection.

### Model versions

`inspection/versions.json` stores local paths, display names, IDs, content identities, file fingerprints, tokenizer identity, capabilities, logical components and transformation metadata. Identifiers are derived from checkpoint content and its canonical local path. Content identity is derived from asset checksums and can match across paths. For manifested assets, import reuses a recorded SHA-256 when size and modification time match. Unmanifested assets and changed files are hashed in bounded chunks. Jobs reject changed checkpoint files until they are imported again. The registry retains original identities for saved recordings and preserves aliases from the initial prototype.

Benchmark runs are linked by the evaluator's asset identity. Score deltas require completed results, the same protocol hash, metric, sample count and exact ordered question IDs. The ALS variant's parent is inferred from the shared pinned repository and revision and its recorded weight-only ALS transformation. Stored parameter totals come from serialized tensors. Qwen3's tied embeddings and output head share a single stored tensor in these checkpoints.

### Component correspondence

Qwen3 projections map by logical module name for the verified dense and ALS models with the same source revision. Future transformed checkpoints can supply `component_mappings.json`. Its `comparisons` object is keyed by peer version ID or peer content identity. Each value maps a peer component name to an object with the owning checkpoint's `b_name`, optional `a_indices` and `b_indices` for aligned output channels, and a `status` such as `matched`, `removed` or `unavailable`. Indices on side A refer to the peer. Side B refers to the checkpoint carrying the mapping. Optional retained/removed channel, head or block provenance can accompany these fields. Channel selections are used only when explicit paired indices are present and valid. Reversing the pair reverses correspondence and index orientation. Full weight comparison currently requires native, compatible matrix coordinates.

### Recordings

`inspection/recordings/<id>/recording.json` saves schema version, state, model IDs and hashes, prompt, tokenization settings, token IDs and decoded text, phase and position, module capture summaries, optional raw input/output slices, resource measurements and comparisons. The browser remembers the selected pair, recording and selected token in local storage. Existing prototype recordings remain readable.

Prefill consumes the capped plain prompt. Optional cached decode follows Version A's fixed-length greedy continuation. Version B receives the same continuation tokens in the same positions. Next-token distributions have an explicit prefix position. Activation hooks copy selected positions without modifying outputs. Summary mode persists statistics, and raw mode can persist the first 128 features. The same-input local replay sends captured Version A inputs to the two logical projections. Whole-model relative error uses `||B−A||₂ / ||A||₂`. Equal zero vectors yield zero relative error. A zero reference with a nonzero difference, or cosine with either norm zero, yields unavailable.

Jobs support up to 128 prompt tokens, eight decode tokens, 40 modules and 16 positions. The service caps in-memory capture at 64 MiB per version and raw persistence at 65,536 values per version. It checks for at least 512 MiB of free recording disk and 2 GiB of available RAM before loading each mapped checkpoint. Cancellation takes effect at a job boundary, such as a hook, an inference pass or a matrix tile. Very short linear algebra calls finish before their next cancellation check.

### Weights

Slice statistics describe a maximum of 512 × 512 values. A heatmap displays sampled cells, while its histogram and norms use all finite values in that slice. The optional singular values describe the selected slice. A full weight comparison tiles both logical matrices, reconstructing only factor tiles in FP32, and reduces squared errors in FP64. For a compatible dense/factor pair, the app also measures the fraction of the source matrix's energy captured by the column span of the stored left factor using a thin SVD. This quantity can differ from the energy retained by optimal rank-matched truncated SVD.

## Real-model diagnostic walkthrough

The [browser-submitted recording](../inspection/recordings/20261121T112838Z-609ec6e2/recording.json) uses five prompt tokens for `The capital of France is`, then replays Version A's one-token continuation, ` Paris`. The capture covers positions 4 and 5, all 36 blocks, and the down projections at blocks 0, 17 and 35. Captured and unhooked runs produced bitwise equal logits for both versions.

| Version | Checkpoint load | Hooked forward | Total with parity and local diagnostics | Sampled peak RAM |
| --- | ---: | ---: | ---: | ---: |
| Original Qwen3-4B | 1.14 s | 33.09 s | 44.51 s | 7.67 GiB |
| ALS rank-256 MLP | 56.42 s | 9.05 s | 69.21 s | 3.48 GiB |

The relative output error across the two selected positions was 66.59% at block 0, 85.30% at block 5, 234.39% at block 6, and 175.00% at block 35. Block 6 cosine similarity was 0.146. Relative error can exceed 100% because it divides the difference norm by the original output norm. This identifies a large divergence in the recorded sequence and does not identify which parameter changes caused it.

Same-input projection replay measured relative output errors of 64.55%, 79.34% and 39.13% at the three down projections, respectively. Those measurements isolate the projection response for the recorded Version A inputs. They use a different basis from the full-block output comparisons.

At the prefix ending in ` is`, the original assigned 62.39% probability to ` Paris`, its top token. The ALS version's top token was ID 88774, decoded as a replacement character followed by a line break, at 31.06%. The total variation distance was 0.999998. After both versions received the same ` Paris` token, the original's top token was a period at 80.61%, and total variation distance remained 0.999990.

## Limits

Execution is verified for the local dense Qwen3-4B and ALS rank-256 MLP checkpoints. Generic safetensors support is inventory and bounded weight inspection. Attention probability tensors are unavailable with the optimized attention path. Explicit pruning mappings were checked on synthetic fixtures. No real pruned checkpoint was available. CPU timing includes instrumentation, depends on file caching and RAM pressure, and should be read as diagnostic runtime. The service keeps prompt and activation data locally.

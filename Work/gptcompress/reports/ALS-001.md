# ALS-001 experiment record

Status is in progress. Weight-only ALS implementation and representative probes are complete. Full rank-256 MLP conversion is running. Model accuracy has not yet been measured for a compressed variant.

## Representative results

Six original Qwen3-4B matrices were approximated at rank 256 with 20 FP32 alternating least-squares iterations. The solver uses the rank-revealing `gelsy` driver. Factors are stored in BF16. These are relative squared Frobenius errors.

| Matrix | ALS error | Exact truncated-SVD optimum |
| --- | ---: | ---: |
| Block 0 MLP down | 0.756617 | 0.755951 |
| Block 0 attention key | 0.433108 | 0.432443 |
| Block 18 MLP down | 0.731608 | 0.730940 |
| Block 18 attention key | 0.271148 | 0.270826 |
| Block 35 MLP down | 0.776828 | 0.775973 |
| Block 35 attention key | 0.405247 | 0.404664 |

MLP down matrices went from 24,903,680 parameters to 3,145,728 factor parameters. Attention key matrices went from 2,621,440 to 917,504. Probe peak working set was approximately 1.36 GB. The large residuals at rank 256 show substantial weight information is discarded even near the optimum. They do not establish task accuracy.

Exact commands and artifacts are retained in `experiments/ALS-001-probe-r256/progress.json`. The command recorded for that historical run was `rtk proxy .venv/Scripts/python.exe -u src/compress.py --rank 256 --probe --output experiments/ALS-001-probe-r256` from Work. ## Verification and recovery

Four focused tests pass for known-rank reconstruction, deficient and zero matrices, invalid inputs, the SVD lower bound, direct factor execution, and tiny-Qwen checkpoint reload. A test setup initially rounded rotary buffers by casting the entire reference model to BF16, causing intermittent logit differences. The setup now casts only newly inserted factors, preserving the model's native rotary-buffer precision.

A development baseline was attempted with batch size 10 and the longer development token budgets. Concurrent conversion and evaluation pushed total host memory usage to 97.8%. The evaluation was stopped before scoring any task and its failed record is preserved in `experiments/20261120T231535Z-d2b30f4e`. Further evaluation must run sequentially with a smaller matched batch. Conversion itself uses approximately 1.3 GB working set.
